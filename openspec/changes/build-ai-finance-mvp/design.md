## Context

动机与范围见 proposal.md。仓库目前只有文档，没有应用代码。部署目标是用户自有的一台 VPS（2 核、7.5 GiB 内存、80 GB 磁盘，与其他服务共用，已有 Node 22、pm2 与 acme.sh）。只有用户本人使用。

数据源已在 2026-10-25 实测（见 `docs/data-sources.md` 与 `docs/verification.md`）：FRED 可取得全部宏观序列，但标普 500 只有近 10 年，ICE BofA 利差只有近 3 年，没有罗素 2000 与费城半导体指数；SEC EDGAR 的 XBRL 接口可取得美股公司财报，但科目名称会变、季报为年初累计值、台积电只有年度 20-F；台积电每月以 6-K 报送 SEC。

参考项目 OpenStock（最新提交 `855ca6a`）的数据完全来自 TradingView 嵌入组件与 Finnhub 报价快照，不保存历史序列，没有宏观数据。本设计只参考其 TradingView 组件容器与 EDGAR 访问方式。

以下决定中，标为“默认”的是推荐方案，等待用户审阅后固定。

## Goals / Non-Goals

**Goals:**

- 每个数值可追溯、可复现；缺失、待确认、过期都有明确状态。
- 采集与展示分离：页面打开时不调用外部供应商。
- 免费额度内稳定运行，单台 VPS 资源占用低。
- 规则、公式与科目映射都放在版本化配置中，可以测试与回看。

**Non-Goals:**

- 盘中或秒级更新、多用户、对外公开展示。
- 自建回测平台；信号历史表现只做固定观察期的统计。
- 从 TradingView 嵌入组件提取数据。

## Decisions

### 1. 每日批量采集 + 时间序列存储 + 只读页面

```
调度器（cron）→ 采集命令 → 各来源适配器 → 校验 → 时间序列表
                                               ↓
                                   派生指标与信号计算 → 结果表
                                               ↓
                      Next.js 服务端组件读库 → 浏览器图表
```

| 方案 | 评价 | 选择 |
|---|---|---|
| 批量采集入库，页面只读本地数据 | 免费额度消耗与访问次数无关；可做历史计算、校验与修订记录 | 采用 |
| 打开页面时请求供应商并短期缓存（OpenStock 方式） | 适合实时报价，但无法计算均线、同比与信号历史 | 不采用 |
| 用 Grafana 等现成看板 | 搭建快，但来源追溯、人工录入、信号规则说明与中文布局都要绕开其模型 | 不采用 |

### 2. 语言与运行时（默认）

全栈 TypeScript：Next.js App Router 负责页面与接口，采集任务是同一仓库内的 Node 命令行脚本，共用数据模型与校验代码。运行时使用 Node 22 LTS（VPS 已安装）。

备选：采集部分用 Python（pandas、fredapi 生态更成熟）。代价是两套工具链、两套依赖与类型定义。第一阶段数据量小，TypeScript 足够。

### 3. 存储（默认）

SQLite（WAL 模式）+ Drizzle ORM 与迁移脚本。

| 方案 | 收益 | 代价 | 选择 |
|---|---|---|---|
| SQLite | 单文件、零运维、内存占用低，备份就是复制文件；单用户读多写少完全够用 | 只能单机；并发写有限 | 默认 |
| PostgreSQL | 更标准，以后多用户可直接沿用 | 需要多运行一个服务，与 VPS 上其他服务争用资源 | 备选，Drizzle 可迁移 |
| MongoDB（原方案） | — | 时间序列的对齐、关联查询不方便 | 不采用 |

主要数据表：

| 表 | 内容 |
|---|---|
| `series` | 序列定义：来源、来源代码、中文名、单位、频率、季调、类别、版权方、合理范围、跳变阈值、典型发布延迟 |
| `observations` | `series_id`、`obs_date`、`value`、`status`（正常、待确认）、`source_ref`（链接或申报编号）、`fetched_at`；主键为序列加日期 |
| `observation_revisions` | 被修订前的值、修订发现时间 |
| `derived_values` | 派生指标结果、公式版本、输入状态 |
| `filings` | 申报编号、表单类型、公司、期间、提交日期、链接 |
| `companies` | 代码、CIK、财年结束月、所在层、周期强度、科目映射版本 |
| `manual_entries` | 人工录入值、来源链接、录入与修改历史 |
| `signal_rules`、`signal_states` | 阈值覆盖与修改历史；状态变化日志 |
| `events` | 日程事件、来源、是否确认、关联序列 |
| `ingest_runs` | 任务运行记录、行数、失败原因 |

日期规则：`obs_date` 用来源本身的日期（市场数据按美东交易日），时间戳一律存 UTC，页面显示北京时间，事件同时显示美东时间。

### 4. 数据源适配器

每个来源一个适配器，输出统一的观测结构，供应商可替换。

| 来源 | 方式 | 频率 | 说明 |
|---|---|---|---|
| FRED | 官方 API（需免费密钥） | 日、周、月 | 不使用无密钥的图表 CSV 接口；API 支持查询历史版本 |
| SEC EDGAR | `companyfacts` 与 `submissions` 接口 | 每日检查新申报 | `SEC_USER_AGENT` 由环境变量配置（含联系邮箱，不写入仓库）；请求频率低于 SEC 规定的每秒 10 次 |
| 日线行情 | 默认 Tiingo 免费档，复权收盘价 | 每个交易日 | 约 50 个代码；额度上线前在官网核实 |
| 台积电月营收 | 官网投资者关系页面，用 6-K 交叉核对 | 每月约 10 日 | 页面结构变化时任务失败并报告，不猜测数值 |
| 韩国半导体出口 | 先人工录入，公开接口核实后再自动化 | 每月 1 日、21 日 | — |
| 人工录入 | 页面表单 | 不定期 | 存储价格、云业务增速、资本开支指引、财报日期 |

EDGAR 的科目映射按公司存放在配置文件中，例如 NVDA 的资本开支在 2020 年前后使用不同科目；单季值由累计值相减得到，第四季度用年报减前三季度，测试用四季合计等于年报来校验。

### 5. 校验、修订与时效

每个序列在 `series` 中登记合理范围、跳变阈值（历史标准差的倍数）、频率与典型发布延迟。校验失败的观测存为待确认，不参与派生计算与信号。用户在数据健康页确认或删除。

修订：采集到的值与已存值不同时，旧值写入 `observation_revisions`。信号历史回看默认使用修订后数据并标注前视偏差；FRED 的历史版本查询留作后续改进（见 Open Questions）。

时效：根据频率与发布延迟计算下次预计更新时间，超时即标为过期。

### 6. 派生指标与信号

派生指标（同比、3 个月年化、移动平均、回撤、比值、分位、净流动性）是纯函数，入参为观测序列，输出带公式版本的结果，用固定样本做单元测试。

信号规则存放在仓库的版本化配置中，阈值可在页面覆盖并记录修改历史。默认规则（阈值均可调整）：

| 信号 | 警示条件 |
|---|---|
| 10Y-3M 利差 | 倒挂后转正 |
| 高收益债利差 | 3 个月内上升超过 1 个百分点 |
| 萨姆规则 | ≥ 0.5 |
| 初请失业金 4 周均值 | 较 52 周低点上升 20% 以上 |
| 芝加哥联储金融条件指数 | > 0 |
| 标普 500 | 低于 200 日均线 |
| VIX/VIX3M | > 1 |
| WTI 原油 | 同比上涨 > 50% |
| 10 年期实际利率 | 3 个月内上升超过 0.75 个百分点 |
| 云厂商资本开支合计（1B） | 同比增速连续两个季度下降 |
| 台积电月营收（1B） | 3 个月平均同比转负 |

历史表现：每次触发后 SPY 与 SOXX 3、6、12 个月的涨跌与最大回撤，包括没有出现预期结果的触发。

周期象限：增长轴为工业产出同比相对 3 个月前的变化，通胀轴为核心 CPI 同比相对 3 个月前的变化。定义简单、可解释，页面上公开公式。

### 7. 访问保护（默认）

单一所有者：环境变量配置用户名、Argon2id 密码哈希与会话密钥；登录后发放签名的 HttpOnly、Secure、SameSite Cookie；登录失败限流记录存在数据库中，只有配置了可信代理时才读取转发 IP。

备选：Better Auth（单用户用不上其注册与账户管理）；仅靠 Nginx Basic Auth（没有退出与限流反馈，可以作为额外一层叠加）。

### 8. 前端（默认）

Tailwind CSS，中文、暗色、桌面优先，数值使用等宽数字。全部图表用 ECharts（Apache-2.0），适合长时间序列、多轴与标注区间。TradingView 嵌入组件只用在个股详情的 K 线上，保留其标识与外部链接；容器参考 OpenStock `components/TradingViewWidget.tsx`，改编时登记来源。

页面：`/`（总览：周期象限、信号灯、未来 30 天事件）、`/macro`（六组宏观视图）、`/ai`（1B：产业周期与关注池）、`/stocks/[symbol]`（1B）、`/data`（数据健康与人工录入）、`/login`。

### 9. 调度与部署（默认）

- 应用由 pm2 运行在 VPS 上，经现有反向代理以 HTTPS 提供服务。
- 系统 cron 调用采集命令：每日北京时间 07:30（已覆盖美东夏令时与冬令时的收盘）；CPI、非农、PCE 发布日美东 09:00 追加一次；初请失业金每周四追加一次；EDGAR 每日检查一次；台积电每月 10～12 日每日检查。
- 采集任务失败时写入 `ingest_runs`，并显示在 `/data`；第一阶段不发送推送。
- 数据库每日备份到另一个目录，执行迁移前额外备份一次。

备选：Docker Compose。便于迁移，但单用户场景下比 pm2 加 cron 多一层运维。

## Risks / Trade-offs

- [免费供应商的额度或条款变化] → 适配器可替换；`docs/data-sources.md` 记录核对日期，上线前复核。
- [FRED 第三方序列历史有限：标普 500 只有 10 年，ICE 利差只有 3 年] → 用 SPY、HYG/IEF 等 ETF 替代指标补足长历史，并明确标注。
- [EDGAR 科目映射需要持续维护] → 按公司配置映射；四季合计校验作为测试；缺少映射时显示缺失。
- [信号误报或阈值过拟合] → 页面展示包括失败案例在内的完整历史，不合成评分。
- [修订后数据造成前视偏差] → 明确标注；后续可改用 FRED 历史版本。
- [人工录入负担与遗漏] → 人工序列控制在少数几项，按时效规则提示过期。
- [与其他服务共用 VPS] → SQLite 与短时批处理资源占用低；采集任务限制并发。
- [SQLite 单文件损坏] → WAL 模式、每日备份、迁移前备份。
- [TradingView 组件被下线] → 只用在详情页，加载失败时降级为外部链接。

## Migration Plan

没有已上线的应用，不涉及数据迁移。

1. 1A：建立应用骨架、数据模型、FRED 与日线适配器、校验、宏观页面、信号与日程，在 VPS 上部署并实际运行一周采集。
2. 1B：增加 EDGAR、台积电、人工录入序列与 AI 产业页面。

回滚：pm2 保留上一版构建；数据库迁移只向前，回滚时恢复迁移前的备份。
