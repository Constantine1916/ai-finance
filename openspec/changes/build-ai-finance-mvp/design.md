## Context

这是全新项目，当前只有文档。已确认的产品决定见 proposal；下面的技术与界面方案仍待用户审阅。目标是中长期研究所需的清晰信息组织，不能把数据组件数量当作研究准确性，也不生成买卖建议。

OpenStock 基线为 `dc2db1bb2fdce2da3bb1eba7c51a73ad52f7d464`。参考其 TradingView、Better Auth、MongoDB、自选股、Finnhub 与 Adanos 路径，不复制整套后台任务。源码来源记录见仓库根目录 `THIRD_PARTY_NOTICES.md`。

## Goals / Non-Goals

目标：四个模块可逐项验收；多账户隔离；免费模式可以启动；缺失数据可解释；供应商密钥仅在服务端；公开仓库可复现运行。

非目标：实时交易终端、自动下单、持仓核算、回测、估值模型、付费数据采购，以及 proposal 排除的消息与任务功能。“专业”首先指可追溯的数据、稳定交互与清晰密度，不承诺机构级行情覆盖。

## Decisions

### 1. 采用选择性复用的独立项目

| 方案 | 收益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 独立建仓，参考并选择性改编四个模块 | 保留成熟接入方式，清晰控制范围与许可 | 需重新验证集成和用户隔离 | 推荐 |
| 整体复制上游再删除功能 | 首屏较快成形 | 容易遗留提醒、邮件、无关市场与隐式依赖 | 不采用 |
| 全部组件与数据接入从头实现 | 自由度高 | 增加工期，偏离借用上游实现方式的要求 | 不采用 |

本项目使用 AGPL-3.0。实际改编时记录文件映射并保留原有声明；独立仓库不改变改编源码的许可边界。

### 2. 页面与视觉

默认中文、暗色、高信息密度、桌面优先；上涨绿色、下跌红色，数值使用等宽数字，移动端保持表格可横向阅读。界面包含来源标识，避免用无依据的综合评分填满空白。

| 路由 | 内容 |
| --- | --- |
| `/sign-in`、`/sign-up` | 邮箱密码入口 |
| `/dashboard` | 基准组件、市场热力图、AI 关注池、证券搜索 |
| `/stocks/[symbol]` | 图表、技术、财务、公司信息、情绪摘要、加入自选 |
| `/watchlist` | 当前用户的证券、可用行情、来源时间、删除操作 |
| `/sentiment` | 选择证券，按来源查看情绪与覆盖 |

根路由按会话跳转登录或市场看板。四个业务页面均需登录；只开放认证入口、静态资源与不含敏感信息的健康检查。导航只有四个业务入口。

市场看板默认参考 SPY、QQQ、SOXX 等美国上市 ETF；TradingView 热力图准确标识其覆盖市场，不把标普 500 热力图命名为纳斯达克 100。AI 关注池使用人工维护的产业链标签，初始例子包括 NVDA、AMD、AVGO、MSFT、GOOGL、AMZN、META、PLTR；标签不代表实时指数成分或投资建议。

个股默认日线与适合中长期观察的时间范围。财务、技术、公司信息使用各自的 TradingView 组件；其数据不写入自建 API，也不假设能提取或计算多季度指标。第一版不自行计算缺少历史数据的 RSI、均线、估值或市场宽度。

### 3. 应用边界

采用 Next.js App Router、TypeScript、Tailwind CSS、Better Auth 与官方 MongoDB driver。认证适配器与自选股共用连接管理，不同时引入 Mongoose。应用依赖在实施时选择受支持版本并提交锁文件。

请求路径：浏览器 → 已验证会话的服务端动作 / route handler → 证券校验 → 数据适配层 → 授权检查 → 缓存与配额 → 供应商。TradingView 组件由浏览器按供应商方式加载，不经过自建行情 API。

供应商逻辑集中在服务端模块；页面只接收已规范化结果。用户自选股读取不经过共享数据缓存。认证、页面、供应商与持久化分别有独立职责，避免把访问控制散落在 UI 中。

### 4. 账户与自选股

Better Auth 管理密码哈希与会话，MongoDB 存储账户。第一版没有邮件验证流程，所以界面不声称已核实邮箱归属。支持注册、登录、退出；生产环境采用 HTTPS、安全 Cookie 和同源约束。数据库故障不能降级成免登录。

所有用户资源从服务端会话取得 `userId`；不接受客户端指定资源所有者。认证写操作与注册登录均有限流。应用层限流记录放 MongoDB，跨实例有效；默认以账户与连接来源组合限制，只有显式配置可信代理时才读取其转发 IP。

自选股采用一个用户一份的文档：`_id=userId`、`items=[{symbol, addedAt}]`、`updatedAt`。以条件原子更新保证不存在重复且长度小于 50 才添加；首次文档初始化处理唯一键竞争。删除操作同样以会话用户定位文档。不能先 count 再 insert。超过上限、重复、无效证券有不同反馈。

### 5. 证券目录与符号

从 Nasdaq Trader 的 `nasdaqlisted.txt` / `otherlisted.txt` 导入美国上市证券元数据快照，保留源 URL、生成时间和交易所，排除测试证券，区分股票、ADR 与 ETF。搜索只查本地目录，不在每次输入时消耗 Finnhub 配额。交付时包含可追溯快照与手动更新命令；导入失败保留上一有效版本并标记时间。

目录是上市元数据，不包含虚构报价，也不保证供应商对所有证券有覆盖。维护 canonical symbol 与各供应商 symbol 的映射，对点号、连字符和交易所前缀进行显式转换。非法或不在美国目录中的代码不可直接透传给供应商。无法确定映射时显示未覆盖。

### 6. 数据结果与时效

统一结果包含 `status`、`source`、`fetchedAt`、`expiresAt`、可选 `asOf`、可选 `data` 和可读 `reason`。状态包括 `available`、`unconfigured`、`restricted`、`rate_limited`、`not_covered`、`unavailable`。`asOf` 只能来自供应商实际数据时间，`fetchedAt` 不冒充行情时间。

有效零值和缺失必须不同。数据过期但仍允许使用时，额外标记 `stale=true` 并展示原数据时间与刷新失败原因；授权关闭后不得继续显示缓存数据。没有有效缓存时显示不可用，不生成替代金融数字。内部错误、密钥与供应商原始响应不直接返回浏览器。

### 7. TradingView、Finnhub 与 Adanos

TradingView 保留供应商品牌与归属链接，脚本 URL 使用明确白名单；组件卸载清理容器，切换证券不残留旧配置。外层脚本加载失败或等待超时给出重试与外部查看链接。跨域组件内部的无覆盖信息由组件本身展示，不承诺能检测所有内部失败。详情与市场页面可在 Finnhub / Adanos 未配置时继续使用可用组件。

Finnhub 用于自选股与关注池的独立行情字段。默认缓存 1 小时，公司元数据如接入则缓存 24 小时；自建字段不标注实时。它是可选增强，不是图表数据源。默认 `FINNHUB_SHARED_DISPLAY_ENABLED=false`，只有配置密钥并具备适用的共享展示授权后才启用。配置开关只是操作员声明，不能创造数据授权。

Adanos 按四个来源分别调用：Reddit、X、新闻、Polymarket。默认窗口 7 天，可选 1 / 30 天；按股票、窗口、来源缓存 24 小时。每源保留其原始语义与单位，分别展示 buzz、看涨比例、讨论量或交易数等供应商实际返回的字段。缺失来源不参与任何汇总；第一版不生成跨源平均分、置信度或买卖信号。新闻仅作为情绪来源，不扩展成新闻模块。

默认 `ADANOS_SHARED_DISPLAY_ENABLED=false`。Adanos 免费计划的非商业限制和共享展示适用性须单独核对；不能因为有免费 key 就默认可供本多用户产品展示。当前免费额度为每月 250 次请求；应用默认全实例每月预算 200 次并按 UTC 月份原子计数，预留余量。预算可配置但不得把应用预算当成供应商授权。

### 8. 缓存、失败与配额

MongoDB 保存共享的供应商缓存、带过期时间的刷新租约和配额计数，缓存键包含供应商、规范化证券、来源、窗口及结构版本。应用读取时检查到期时间，不能依赖 TTL 删除的及时性。多实例同时请求相同数据只允许一个有效租约持有者刷新；其他请求有限等待或返回仍可使用的缓存，无缓存且等待到期则返回 `unavailable` 并说明正在刷新。

供应商请求超时默认 5 秒，有限并发。Finnhub 分钟预算与 Adanos 月预算原子预留后才发请求；不回退已发请求的计数。429 写入共享冷却期限并遵从有效的 Retry-After，无自动立即重试。网络错误不无限重试；前端刷新不能绕过缓存或配额。无密钥、无授权、未登录请求不消耗供应商额度。

用户会话、邮箱、自选股和供应商密钥不进入公共缓存或浏览器包。数据库不可用时，受保护动作明确失败，不绕过预算调用供应商。

## Risks / Trade-offs

- 免费方案可以完成页面、账户、自选股及嵌入集成，但不能保证所有独立行情与情绪字段可用。真实覆盖必须在合法凭据下验证。
- TradingView 的可用性、延迟、证券覆盖与语言由供应商控制，订阅个人行情不等于提升嵌入组件权限。
- MongoDB 缓存与计数比单进程 Map 多一些实现成本，但避免多用户部署时额度与并发约束失效。
- 邮件验证和密码重置尚不在第一版；不得在文档中承诺已交付。若要向公开互联网提供完整账户恢复体验，另立变更。

## Delivery / Verification

先实现认证、目录与数据状态基础，再接入四个模块，最后完成集成和交付。首版提供 `.env.example`、本地启动、Docker Compose、CI 与数据源说明；运行时注入密钥，MongoDB 不默认暴露到公共网络。构建不依赖真实供应商密钥或在线数据库。

必须验证：类型检查、lint、生产构建；真实 MongoDB 上的账户隔离、持久化和并发 50 只上限；缺失配置零出站调用、429 冷却、跨实例请求去重、部分来源失败、缓存与过期语义；浏览器注册登录、自选股和四路由流程。测试夹具只在显式测试环境使用。

真实 TradingView 浏览器检查与 Finnhub / Adanos 实测独立记录。没有凭据或授权时记录未执行，不能用模拟响应替代真实验证结论。OpenSpec 校验只检查文档结构，应用实现通过验收前不归档。
