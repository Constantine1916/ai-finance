## Context

动机与范围见 proposal.md。仓库目前只有文档，没有应用代码。部署目标是用户自有的一台 VPS（2 核、7.5 GiB 内存，约 4.2 GiB 已被其他服务占用；80 GB 磁盘）。机器上已有 Node 22、pm2、Docker、acme.sh，Nginx 监听 80 与 443；`aicave.cn` 已解析到这台机器，现有证书只覆盖 `aicave.cn` 与 `www.aicave.cn`。另一个项目在 Docker 中运行 PostgreSQL 17。只有用户本人使用。

数据源已在 2026-10-25 至 10-26 实测（见 `docs/data-sources.md` 与 `docs/verification.md`）：

- FRED 可取得全部宏观序列，但标普 500 只有近 10 年，ICE BofA 利差只有近 3 年，没有罗素 2000 与费城半导体指数；日度利率比美国财政部官网晚一天。
- 美国财政部官网当日公布收益率曲线；BLS API 无密钥即可取得 CPI 等序列。
- SEC EDGAR 可取得美股公司财报，但科目名称会变、季报为年初累计值、台积电只有年度 20-F；台积电每月以 6-K 报送 SEC。
- Finnhub 免费密钥实测：报价可用，历史 K 线返回 403，指数报价需要付费订阅；OpenStock 也只用它取报价快照。

参考项目 OpenStock（最新提交 `855ca6a`）的数据来自 TradingView 嵌入组件与 Finnhub 报价快照，不保存历史序列，没有宏观数据。本设计参考其 Finnhub 报价用法、TradingView 组件容器与 EDGAR 访问方式。

用户已确认：PostgreSQL、全栈 TypeScript、pm2 与 cron 部署、`finance.aicave.cn` 部署、默认信号阈值、关注池可编辑、优先保证时效性。仍待确认的只有标为“待确认”的项目。

## Goals / Non-Goals

**Goals:**

- 时效性：官方数据发布后尽快可见；交易时段内价格信号基于盘中快照。
- 每个数值可追溯、可复现；缺失、待确认、过期、盘中暂定都有明确状态。
- 采集与展示分离：页面打开时不调用外部供应商。
- 免费额度内稳定运行，单台 VPS 资源占用低。
- 规则、公式与科目映射都放在版本化配置中，可以测试与回看。

**Non-Goals:**

- 逐笔或秒级行情、多用户、对外公开展示。
- 自建回测平台；信号历史表现只做固定观察期的统计。
- 从 TradingView 嵌入组件提取数据。

## Decisions

### 1. 采集入库 + 页面只读

```
pm2: worker（调度器）→ 各来源适配器 → 校验 → PostgreSQL 时间序列表
                                              ↓
                              派生指标与信号计算 → 结果表
                                              ↓
              pm2: web（Next.js 服务端组件读库）→ 浏览器图表
```

| 方案 | 评价 | 选择 |
|---|---|---|
| 采集入库，页面只读本地数据 | 额度消耗与访问次数无关；可做历史计算、校验与修订记录 | 采用 |
| 打开页面时请求供应商并短期缓存（OpenStock 方式） | 适合报价，但无法计算均线、同比与信号历史 | 不采用 |
| 用 Grafana 等现成看板 | 来源追溯、人工录入、信号说明与中文布局都要绕开其模型 | 不采用 |

### 2. 时效分层

| 数据 | 来源 | 采集方式 | 目标延迟 |
|---|---|---|---|
| 关注池与大盘 ETF 盘中快照（约 50 个代码） | Finnhub `/quote`（免费，每分钟 60 次） | 美股交易时段每 5 分钟一轮，约每分钟 10 次请求 | ≤ 5 分钟加供应商自身延迟 |
| 复权日线收盘 | Tiingo（待核实） | 美东 18:30 一次，次日北京时间 07:30 补采 | 收盘后数小时 |
| 国债收益率曲线 | 美国财政部官网 | 美东 16:00 起每 15 分钟，取到当日数据为止；次日用 FRED 交叉核对 | 当日 |
| CPI、非农 | BLS API | 发布日美东 08:30 起每 2 分钟，最长 60 分钟 | ≤ 15 分钟 |
| PCE | BEA API（免费密钥） | 发布日美东 08:30 起每 2 分钟，最长 60 分钟 | ≤ 15 分钟 |
| 初请失业金 | FRED（劳工部发布后更新） | 每周四美东 08:30 起每 10 分钟，最长 3 小时 | 当日上午 |
| 信用利差、VIX、金融条件、美联储资产负债表等 | FRED | 每日两次 | 次日（没有更快的免费来源） |
| 财报 | EDGAR `submissions` | 平时每小时一次；财报日美东 16:00～20:00 每 10 分钟 | ≤ 15 分钟 |
| 台积电月营收 | 官网，6-K 交叉核对 | 每月 10 日起每小时，取到为止 | ≤ 1 小时 |

盘中快照存在单独的表中，标为盘中暂定，不写入日线历史；收盘后的复权日线是正式值。同一指标有更早发布的官方来源时优先使用它，后到的来源用于交叉核对，不一致则标为待确认。

发布日的追加采集由 `events` 表中的官方日程驱动，自动处理美国夏令时切换。用固定的 cron 表达式写不出这一点，所以调度放在 pm2 管理的 worker 进程里；系统 cron 只负责数据库备份和检查 worker 是否存活。这是对“pm2 + cron”方案的细化。

### 3. 语言与运行时（已确认）

全栈 TypeScript：Next.js App Router 负责页面与接口；worker 是同一仓库内的 Node 进程，共用数据模型、适配器与校验代码。运行时 Node 22 LTS。

实施时固定的版本（2026-10-26）：Next.js 16.4.3、React 19.3.0、TypeScript 6.0.3、ESLint 9.39.5、Vitest 5.0.3、Drizzle ORM 0.45.4、PostgreSQL 17.9。取舍：

- TypeScript 7 是新的原生编译器，Next.js 构建、typescript-eslint 与 Drizzle 依赖的编译器 API 不在其兼容承诺内，因此用 6.x。
- ESLint 10 不被 `eslint-config-next` 内置插件支持，因此用 9.x。
- Next.js 16.4.0 存在已公布的严重漏洞（GHSA-2464-fhr4-w9xw、GHSA-673q-mjm6-r5xr 等），升级到修复版 16.4.3；该版本发布不足两周，安全修复优先。
- 全局 npm 10.9.4 解析 Vitest 依赖时崩溃，项目用 `packageManager` 固定 npm 11.21.0。
- 端口：PostgreSQL 用 127.0.0.1:5434（5433 已被其他项目占用），web 用 127.0.0.1:3020。

### 4. 存储（已确认 PostgreSQL）

PostgreSQL 17 + Drizzle ORM 与迁移脚本。

| 部署方式 | 评价 | 选择 |
|---|---|---|
| 独立的 PostgreSQL 17 Docker 容器，只监听 127.0.0.1，数据卷持久化 | 与机器上现有的运维方式一致，与其他项目隔离 | 默认 |
| 在另一个项目的 PostgreSQL 实例里新建数据库与用户 | 省一个进程（约 100 MB 内存） | 与其生产数据库共用故障范围、升级节奏与备份，不采用 |
| 系统包安装（OpenCloudOS 提供 15 与 16） | 不依赖 Docker | 备选 |

主要数据表：

| 表 | 内容 |
|---|---|
| `series` | 序列定义：来源、来源代码、中文名、单位、频率、季调、类别、版权方、合理范围、跳变阈值、发布延迟、时效目标 |
| `observations` | 通过校验的观测：`series_id`、`obs_date`、`value`、`source_ref`、`fetched_at`；主键为序列加日期 |
| `pending_observations` | 未通过校验的观测及原因，单独存放，不覆盖已通过的值；确认后并入 `observations`，只因跳变待确认的值在下次采集得到相同结果时自动确认 |
| `intraday_snapshots` | 代码、快照时间、价格、供应商时间戳；只保留最近若干交易日 |
| `observation_revisions` | 被修订前的值、修订发现时间 |
| `derived_values` | 派生指标结果、公式版本、输入状态 |
| `filings` | 申报编号、表单类型、公司、期间、提交日期、链接 |
| `universe_members`、`universe_changes` | 关注池当前成员（层、周期强度、是否计入云厂商汇总）与修改历史 |
| `companies` | 代码、CIK、财年结束月、科目映射版本 |
| `manual_entries` | 人工录入值、来源链接、录入与修改历史 |
| `signal_rules`、`signal_states` | 阈值覆盖与修改历史；状态变化日志 |
| `events` | 日程事件、来源、是否确认、关联序列、追加采集计划 |
| `ingest_runs` | 任务运行记录、行数、延迟、失败原因 |

日期规则：`obs_date` 用来源本身的日期（市场数据按美东交易日），时间戳一律存 UTC，页面显示北京时间，事件同时显示美东时间。

备份：每日 `pg_dump` 到另一个目录，保留 14 天；执行迁移前额外备份一次。

### 5. 数据源适配器

每个来源一个适配器，输出统一的观测结构，供应商可替换。各来源的鉴权、频率与限制见第 2 节与 `docs/data-sources.md`。补充约定：

- FRED 使用带密钥的官方 API，不使用无密钥的图表 CSV。
- EDGAR 的 User-Agent 由环境变量 `SEC_USER_AGENT` 配置（含联系邮箱，不写入仓库），请求频率低于每秒 10 次。
- Finnhub 只用一个密钥，不像 OpenStock 那样轮换多个免费密钥。
- 日线行情用 Tiingo，用户注册免费密钥后核实额度与个人使用条款；不满足时换供应商，不影响规格。2026-10-26 已用免费密钥实测 Finnhub：报价可用，K 线返回 403，指数（如 VIX）报价需要付费订阅，所以 Finnhub 只用于股票与 ETF 的盘中快照。
- 韩国半导体出口先人工录入。

EDGAR 的科目映射按公司存放在配置文件中，例如 NVDA 的资本开支在 2020 年前后使用不同科目。单季值由累计值相减得到，第四季度用年报减去前三季度，测试时用四季合计等于年报来校验。

### 6. 关注池编辑

关注池成员存在数据库中，在 `/ai` 页面编辑：新增、移除、调整层与周期强度、设置是否计入云厂商资本开支汇总，每次修改写入 `universe_changes`。

- 新增时用 SEC 的 `company_tickers_exchange.json` 查 CIK 与交易所，查不到的拒绝；有效代码立即排入补采：历史日线与申报数据。补采完成前，相关字段显示采集中。
- 移除只停止采集并从当前视图隐藏，历史数据保留。
- 每次修改都检查盘中快照的请求量：代码数 × 每小时轮数，超过 Finnhub 额度的 80% 时拒绝保存，并提示可以降低频率。

### 7. 校验、修订与时效

每个序列在 `series` 中登记合理范围、跳变阈值（历史标准差的倍数）、频率、发布延迟与时效目标。校验失败的观测存为待确认，不参与派生计算与信号，用户在数据健康页确认或删除。

修订：采集到的值与已存值不同时，旧值写入 `observation_revisions`。信号历史回看默认使用修订后数据，并标注前视偏差。

时效：页面上每个数值显示距今多久；超过时效目标或预计发布时间仍未更新的，标为延迟或过期。

### 8. 派生指标与信号

派生指标（同比、3 个月年化、移动平均、回撤、比值、分位、净流动性）写成纯函数，用固定样本做单元测试。

信号规则存放在仓库的版本化配置中，阈值可在页面覆盖并记录修改历史。基于价格的信号在交易时段用盘中快照计算，显示为盘中暂定；收盘确认后才写入状态日志与历史统计。默认规则如下（用户已确认）：

| 信号 | 警示条件 |
|---|---|
| 10Y-3M 利差 | 倒挂后转正 |
| 高收益债利差 | 3 个月内上升超过 1 个百分点 |
| 萨姆规则 | ≥ 0.5 |
| 初请失业金 4 周均值 | 较 52 周低点上升 20% 以上 |
| 芝加哥联储金融条件指数 | > 0 |
| 标普 500（SPY） | 低于 200 日均线 |
| VIX/VIX3M | > 1 |
| WTI 原油 | 同比上涨超过 50% |
| 10 年期实际利率 | 3 个月内上升超过 0.75 个百分点 |
| 云厂商资本开支合计（1B） | 同比增速连续两个季度下降 |
| 台积电月营收（1B） | 3 个月平均同比转负 |

历史表现：统计每次触发后 SPY 与 SOXX 在 3、6、12 个月的涨跌与最大回撤，包括触发后没有出现预期结果的情况。

周期象限：增长轴为工业产出同比相对 3 个月前的变化，通胀轴为核心 CPI 同比相对 3 个月前的变化。页面上公开公式。

### 9. 访问保护

单一所有者：环境变量配置用户名、Argon2id 密码哈希与会话密钥；登录后发放签名的 HttpOnly、Secure、SameSite Cookie。登录失败限流记录存在 PostgreSQL 中；Nginx 配置为可信代理，应用只信任它传入的转发 IP。

### 10. 前端

Tailwind CSS，中文、暗色、桌面优先，数值使用等宽数字。全部图表用 ECharts（Apache-2.0）。TradingView 嵌入组件只用在个股详情的 K 线上，保留其标识与外部链接；容器参考 OpenStock 的 `components/TradingViewWidget.tsx`，改编时登记来源。盘中数据每分钟自动刷新一次页面数据，只读本地库。

页面：`/`（总览：周期象限、信号灯、未来 30 天事件）、`/macro`（六组宏观视图）、`/ai`（1B：产业周期与关注池编辑）、`/stocks/[symbol]`（1B）、`/data`（数据健康与人工录入）、`/login`。

### 11. 部署（已确认 pm2 + cron）

- pm2 运行两个进程：`web`（Next.js，只监听 127.0.0.1）与 `worker`（调度与采集）。
- Nginx 为子域名新增站点，反向代理到 `web`。用 acme.sh 为子域名单独签发证书，现有证书不覆盖子域名。
- 域名：`finance.aicave.cn`。阿里云 DNS 的 A 记录已于 2026-10-26 添加，指向 `101.32.243.232`。
- 系统 cron：每日 `pg_dump` 备份；每 5 分钟检查 worker 心跳，失联时由 pm2 重启并记录。
- 采集失败写入 `ingest_runs`，显示在 `/data`；第一阶段不发送推送。

## Risks / Trade-offs

- [免费供应商的额度或条款变化] → 适配器可替换；`docs/data-sources.md` 记录核对日期，上线前复核。
- [Finnhub 免费报价的延迟与覆盖不明确，比如是否包含指数] → 只对股票与 ETF 取快照，页面显示供应商时间戳；VIX 等指数以 FRED 日度数据为准。
- [盘中快照让信号来回翻转] → 盘中状态只显示为暂定，收盘确认后才记入日志与历史统计。
- [发布日的轮询给官方接口带来压力] → 取到新数据即停止，设置等待上限，遵守各来源的频率规范。
- [FRED 第三方序列历史有限] → 用 SPY、HYG/IEF 等 ETF 替代指标补足长历史，并明确标注。
- [EDGAR 科目映射需要持续维护] → 按公司配置映射；四季合计校验作为测试；缺少映射时显示缺失。
- [关注池扩大导致额度不足] → 保存前检查请求量，超过额度的 80% 时拒绝。
- [信号误报或阈值过拟合] → 页面展示包括失败案例在内的完整历史，不合成评分。
- [修订后数据造成前视偏差] → 明确标注；后续可改用 FRED 历史版本。
- [与其他服务共用 VPS] → 独立的 PostgreSQL 容器约占 100～200 MB 内存；采集限制并发；部署前确认剩余内存。

## Migration Plan

没有已上线的应用，不涉及数据迁移。

1. 1A：建立应用骨架、PostgreSQL 与迁移、适配器（FRED、财政部、BLS、BEA、Finnhub、日线）、校验与时效、宏观页面、信号与日程；部署到子域名，实际运行一周。
2. 1B：增加 EDGAR、台积电、人工录入序列、可编辑关注池与 AI 产业页面。

回滚：pm2 保留上一版构建；数据库迁移只向前，回滚时恢复迁移前的备份。
